# Design context

## Target audience

The operator who runs this fleet — in practice, one person plus the AI agents
they supervise. They open the dashboard in two distinct modes:

1. **Diagnosis** (the urgent mode): something is stuck. A job will not start, an
   agent is blocked, a card went out of the pool. They need to find the cause
   fast and act on it.
2. **Glance** (the ambient mode): a quick look to answer "what is running, what
   is free, is anything wrong?" without reading carefully.

The interface must serve both. Glance mode is the common case; diagnosis mode is
the one that matters when it happens.

## Use cases

- See at a glance which devices are free, busy, or out of the pool, and who
  holds what.
- Find out *why* a device left the pool, and what to do about it.
- See how long something has been running or queued — including a job that has
  been waiting far longer than it should.
- Kill a job the operator submitted; clear a device that has been quarantined.
- Read a host's usage sheet to learn how that machine is meant to be used —
  including how to reach it.

## Tone

**Calm status board.** Quiet and spacious. Large legible state, generous
whitespace, a muted palette that stays calm until something is actually wrong —
and then is unmistakable. Readable at a glance and from across the room. It
should not look like a control panel bristling with instrumentation, and it
should not shout.

## Known problems with the current page (operator's own words: "really raw")

- **Jargon leaks through.** `unhealthy`, `fault`, `quarantine_reason`, `lease`
  are internal vocabulary rendered raw. A reader has to already know the model
  to understand the screen.
- **Commands dominate the layout.** The full shell command line is the widest
  thing on screen, pushing who/how-long/what-state into the margins. The command
  is rarely what the reader came for.
- **No sense of time or trend.** Everything is an instantaneous snapshot. You
  cannot see that a job has been queued for 40 minutes, or that this card has
  failed verification three times today.

## Constraints

- Single self-contained `internal/server/dashboard/index.html`, `go:embed`-ed
  into the controller. **No external requests of any kind** — no CDN, no fonts,
  no scripts, no images. This is a hard security boundary, not a preference.
- Inline CSS and JS only. No build step, no framework.
- Must work in both light and dark, following the viewer's system preference.
- Every user-controlled string (device IDs, commands, submitters, server error
  text) must be inserted as a text node, never as markup.
- The client token lives in `sessionStorage`; the admin token is prompted per
  action and never stored anywhere.
